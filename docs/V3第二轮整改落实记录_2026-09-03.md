## 1. NEW-SEC-001：Public READ 收紧为 Market READ Allowlist ✅

### 问题（复验报告 §3.1 / §4）

`V3AuthPolicy.required_scope()` 旧逻辑：GET 仅 `/portfolio` 前缀要 `PORTFOLIO_READ`，
其余全部 GET 匿名公开——`/watchlist`、`/decisions`、`/reviews`、`/performance`、
`/task-runs`、`/task-context/{profile}`、`/strategies*`、`/strategies/releases/{env}`、
`/release/resolution`、`/entry-plans/{id}/versions`、`/watchlist/changes`、
`/stocks/{id}/decision-pipeline`、`/portfolio-preferences`（别名绕开）等私有/控制面
数据全部可匿名读取。

### 方案

黑名单不可持续（新路由默认公开）。改为**默认拒绝 + 显式 Allowlist**：

- `app/v3/security.py` 新增模块级常量与函数：
  - `PUBLIC_MARKET_READ_EXACT`：纯市场事实精确路径
    （`/universe/features`、`/universe/query`、`/market-regime`、`/market-overview`、
    `/candidates/comparison-pack`、`/recalls`、`/recalls/misses`、`/raw-opportunities`、
    `/market-reviews`、`/market/intraday-status`、`/health/data-quality`）；
  - `PUBLIC_MARKET_READ_PREFIXES`：`/evidence/`、`/context-packs/`；
  - `PUBLIC_MARKET_READ_TEMPLATES`：通配段模板 `("stocks","*","evidence")`、
    `("stocks","*","context-pack")`（按 `/` 分段匹配，`*` 匹配单段）；
  - `is_public_market_read(path)`：接收去掉 `/api/v3` 前缀的相对路径。
- `required_scope()` 新逻辑：
  - 非 `/api/v3` → None（不变）；OPTIONS → None（不变）；
  - 非 GET/HEAD → `V3_WRITE` / `STRATEGY_ADMIN`（不变）；
  - `/portfolio` 前缀 → `PORTFOLIO_READ`（不变）；
  - **`/portfolio-preferences` 别名 → `PORTFOLIO_READ`**（封住别名绕开）；
  - `public_market_read=True` 且命中 allowlist → None（匿名）；
  - **其余 GET/HEAD → `MARKET_READ`**（任何有效 token 均持有该 scope，
    匿名一律 401；`public_market_read=False` 时全量 GET 仍 `MARKET_READ`，语义不变）。

### 测试（tests/v3/test_v3_auth.py）

- 新增 `PUBLIC_MARKET_PATHS`（11 条 allowlist 路径）匿名 200 矩阵；
- 新增 `PRIVATE_READ_PATHS`（10 条私有/控制面路径）匿名 401 且
  `required_scope == MARKET_READ`；同路径带 token 200 矩阵；
- `/portfolio-preferences` 别名：匿名 401、token 200 且 principal 注入；
- 原 `test_market_read_can_be_protected_by_configuration`（全量保护开关）保留通过。

### 连带修复

- 新增 `tests/conftest.py`：测试进程固定 `V3_API_TOKEN`（os.environ 优先级高于
  `.env`，且先于 `app.main` 导入生效），避免收紧后依赖开发者本地 .env 差异；
- `tests/v3/test_error_envelope.py`：走真实 `app.main` middleware 的
  `_test/*` 错误矩阵、watchlist 校验错误、未知路由 404 改为带 token 请求
  （错误断言本身不变）。

### 结果

`tests/v3` 全量：**329 passed, 89 skipped**（原 325 passed，+4 为新增矩阵测试）。

## 2. NEW-SEC-002：Principal 全绑定 + NEW-AUD-001 request_id 传播 ✅

### 问题（复验报告 §3.2 / §3.8 / §4）

- `bind_v3_principal()` 只覆盖 `actor_id/actor_type/confirmed_by`，
  `created_by/corrected_by` 仍信任客户端声明（StrategyVersion/Guardrail/Experiment
  的 `created_by`、DecisionCorrection 的 `corrected_by`）；
- 4 个写端点根本没做 principal 绑定：`/decisions/{id}/corrections`、
  `/strategies/versions`、`/strategies/guardrails`、`/strategies/experiments`；
- Application Service 均已支持 `request_id` kwarg，但 `app/api/v3.py` 从未传入，
  AuditEvent.request_id 大量为 null（NEW-AUD-001）。

### 修复

**security.py**：`bind_v3_principal()` 新增 `created_by`、`corrected_by`
无条件覆盖（两者均为必填字段，服务端 principal 是唯一可信来源）。

**api/v3.py**：
- 新增 `_request_id(request)` helper（principal.request_id；未认证 → None）；
- 4 个缺失绑定端点补 `request: Request` + `_bind_principal`；
- request_id 传播到全部 audited service 调用（16 处）：
  - AI Confirm：`ConfirmAIResultImportService.execute(..., request_id=...)`
    （`import_ai_results.py` 的 `AuditRecorder.record` 同步接线）；
  - Portfolio 8：correct_trade_draft / correct_position_draft / confirm_trade /
    add_opening / confirm_position_draft / add_adjustment /
    add_trade_correction / add_reconciliation；
  - Decision 2：transition_watchlist / add_correction；
  - Strategy 6：add_strategy_version / add_proposal / add_experiment /
    experiment_event / activate / rollback。

**不越界说明**：`/actions`、`/entries` 命令对象无身份字段，无需绑定；
`add_guardrail` / `shadow_observation` / capacity / health-event 服务本身
没有 AuditRecorder 调用（审计覆盖缺口属另一问题，不在本项范围内伪造接线）。

### 测试（tests/v3/test_v3_auth.py）

- `test_created_by_and_corrected_by_are_overwritten_by_principal`：
  StrategyVersionCreate.created_by、DecisionCorrectionCommand.corrected_by
  客户端伪造值 → 覆盖为 principal_id；原 command 对象不被修改（不可变语义保留）。

### 结果

`tests/v3` 全量：**330 passed, 89 skipped**。

## 3. NEW-OPS-001 + NEW-OCR-001：部署 Source of Truth 固化 ✅

### 问题（复验报告 §3.2 / §3.10 / §4）

- `docker-compose.yml` worker 仍是 `python -m scripts.v3_phase2_scheduler`，
  新部署/灾备会回落旧 Worker，仓库 IaC ≠ 生产事实；
- worker healthcheck `disable: true`，无进程级存活探测；
- OCR 图片存储默认 `data/v3-images`（相对路径），容器 rootfs 只读，
  服务器靠手工 env `V3_IMAGE_STORE_DIR=/data/v3-images` 兜底，Git 无固化。

### 修复

**docker-compose.yml**：
- `v3-market-worker.command` → `alembic upgrade head && python -m scripts.v3_scheduler`
  （正式 Orchestrator；Phase2 market job 已并入主链 market-data Job）；
- worker healthcheck → `pgrep -f 'scripts.v3_scheduler'`（60s 间隔，进程存活
  探测，不做 DB 深检避免误杀）；
- worker 补 `./data:/data` 只读挂载（与 API 容器一致）+
  `V3_IMAGE_STORE_DIR=/data/v3-images`；
- `market-mcp` 补 `V3_IMAGE_STORE_DIR=/data/v3-images`（OCR 上传走 API 容器，
  volume 原本就有，缺的是路径 env）。

**.env.example**：
- 新增 `V3_SCHEDULE_AT=18:45`、`V3_INTRADAY_INTERVAL_SECONDS=300`、
  `V3_EVIDENCE_MAX_BATCHES=1`（正式调度器三参数）；
- 新增 `V3_IMAGE_STORE_DIR=/data/v3-images` + 只读容器说明；
- `V3_PUBLIC_MARKET_READ` 注释更新为 NEW-SEC-001 allowlist 语义。

**docs/deployment.md**：
- Worker 段落改写为正式调度器主链/维护链/盘中循环说明；
- 2026-09-01 部署记录中 Worker 条目保留历史事实，注明 NEW-OPS-001 后
  Compose 已统一下次重建即一致；
- V3 安全边界段落补 allowlist + created_by/corrected_by + request_id。

### 验证

- `yaml.safe_load` 解析 compose OK，worker command 确认新调度器；
- `python -m scripts.v3_scheduler --help` 入口正常；
- 无代码行为变更（IaC/配置/文档），`tests/v3` 无影响面。
