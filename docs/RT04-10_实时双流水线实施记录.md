## 补全：EOD 主链 Evidence / Full Recall 段（2026-09-03）

> 缺口：设计 §7.2 Step 09-11（Evidence 增量 → Full Recall → Raw Opportunity Publish）
> 一直靠手动脚本（v3_phase4/5）驱动，生产从未自动跑过——Raw Opportunities 初始全 0 的根因之一。
> 本次将三段并入主链 Orchestrator，幂等键 = trade_date，随 RT-05 retry/catch-up 一并生效。

### 变更（`scripts/v3_scheduler.py`）

| Job | 依赖 | 行为 |
| --- | --- | --- |
| `evidence-increment` | features | 24h 窗口 Evidence 增量，复用 `build_registry`（公告/财报/业绩/政策/新闻）；`V3_EVIDENCE_MAX_BATCHES` 默认 1 |
| `full-recall` | evidence-increment | 12 通道 Full Recall；优先取同编排 features Job 的 `feature_run_id`（context.artifacts），追平/重跑退回最新 PUBLISHED run；RawOpp 与 Observation 由 `RunMultiRecallService.publish` 一并落库（Step 11 无独立 Job） |

### 失败策略（生产诚实原则）

- Evidence：部分能力失败不阻断，如实记入 `failed_capabilities`；仅**全部**能力失败才 FAILED（与 index-benchmarks 一致）
- Recall：通道自带可用性声明（`failed_channel_count`/errors）；非 PUBLISHED 才 FAILED
- Recall 的 Feature Run 解析：`_resolve_feature_run_id()` artifacts 优先 → 最新 PUBLISHED run 兜底 → 都没有报错

- `_evidence_failed_capabilities`：部分失败上报、全成功空表
- `_resolve_feature_run_id`：artifacts 优先 / latest run 兜底 / 缺失报错

## 补全：Regime stale 比例阈值 + stale_reason（2026-09-03）

> 缺陷：`calculate_market_regime.py` 旧规则 `stale = not usable or any(item.stale)`
> ——**任意单票 stale 都会把整个市场 regime 判 stale**（2026-09-02 生产中 002274
> 复牌曾单票拖垮全局）。用户拍板改为比例阈值 + 原因透传（设计 §23.3）。

### 新规则（`regime-stale-ratio-v1`）

```
stale_ratio = stale 行数 / 总行数
stale = true  仅当：无行（no_rows）｜全部行 stale（all_rows_stale）｜比例 > 阈值（stale_ratio_above_threshold）
阈值默认 0.2（严格大于），构造参数 stale_ratio_threshold 可调
```

- 快照新增 `stale_reason`：`rule_version/threshold/stale_count/total_count/stale_ratio/cause`
  ——无论 stale 真假都如实记录，审计可追
- 宽度/换手等市场聚合仍只用非 stale 行（不变），单票 stale 不再污染 stale 标志

### 变更文件

- `app/v3/application/calculate_market_regime.py`：比例规则 + reason
- `app/v3/domain/features.py`：`MarketRegimeSnapshot`/`PublishedMarketRegimeView` 契约加 `stale_reason`
- `app/v3/infrastructure/db/models.py` + `migrations/versions/0017_regime_stale_reason.py`：

- API `/api/v3/market-overview`、`/market-regime` 自动带出 `stale_reason`
