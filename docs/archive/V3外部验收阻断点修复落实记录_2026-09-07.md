## 1. FC-01 ActivePlan 语义

**报告指控**：POSITION record 不应来自 Watchlist-only Plan；绑定应认修正链
后仍有效的最新 BUY；多账户同证券维度缺失；POSITION 与 ENTRY_WATCHLIST
被合成复合来源；持仓无绑定错误回退。

**修复**（`decision_repositories.py`）：

1. `active_price_trigger_plans` 绑定查询重写：遍历 `trade_ledger`（按
   `(account_id, security_id, trade_time DESC, ledger_sequence DESC)` 排序），
   按 trade 分组加载 `trade_corrections`，经
   `apply_trade_correction_chain(EffectiveTradeState(...), steps)` 求有效态；
   `effective.reversed` 或 `side != BUY` 的 trade 不充当绑定，回退上一笔
   有效 BUY。链校验失败抛 `RepositoryConflictError`。
2. `_filter_active_plans` 签名改为
   `trade_binding: dict[tuple[UUID, UUID], tuple[UUID, int]] | None`——键从
   security_id 升级为 `(account_id, security_id)`；TRADE_BOUND plan 按
   绑定 pair 展开，每 pair 一条 record（多账户各绑各的 plan）。
3. POSITION 与 ENTRY_WATCHLIST 严格分离：同一 plan 只以单一 plan_source
   出 record，绝不合成 `ENTRY_WATCHLIST+POSITION + DECISION binding`；
   `in_position and not in_watchlist` 且无绑定 → 直接跳过（不回退
   Watchlist-only Plan）。
4. `_monitor_record` 增加 `account_id` 字段；新增
   `TradeCorrectionModel` import（models 字母序）。

**测试**：`test_active_entry_plan_filter.py` 扩展（ACCOUNT_A/B、tuple 键、
三新用例：无绑定只出 watchlist / 绑定后出两条 record / 多账户各自绑定）；
新建 `test_active_plan_postgres.py` 真实 PG 验收（REVERSE 回退、多账户、
无绑定 watchlist-only，完整 FK 链播种 + DB 读回值构造 hash 链）。

## 5. FC-05 Runtime Factory 统一 HTTP/MCP 只读装配

**报告指控**：HTTP Decision Context / MCP 自建第二套
Intraday/Deep/Structure 服务，绕过唯一 Runtime Factory。

**修复**：

- `runtime.py`：`V3Runtime` 增加 `structure_service` 字段，
  `build_v3_runtime` 构造 `IntradayStructureSnapshotService(intraday_market_data)`
  ——bars 源与 `runtime.intraday_market_data` 是同一实例（同源硬约束）；
- `api/v3.py`：新增 `_v3_runtime_read_only()` 模块级缓存
  （`build_v3_runtime(_uow, container.provider_manager, engine=None)`）；
  三个 HTTP 路径全部改走 runtime：
  - `/stocks/{code}/decision-context` → `runtime.intraday_market_data` +
    `runtime.structure_service`；
  - `/portfolio/intraday/{code}` → `runtime.deep_service`；
  - `_position_context_service()`（`/portfolio/{code}/decision-context`
    与 `/portfolio/{code}/context`）→ `runtime.deep_service` +
    `runtime.intraday_market_data`；
  删除文件头部三处自建 service import；
- `mcp/v3_tools.py`：新增 `_runtime_read_only()`（缓存键 `"runtime"` 存
  完整 V3Runtime，engine=None）；`_bars_service()` /
  `_structure_service()` / `_fast_lane_read_only()` 全部改为从该 runtime
  取对应 service；`_position_context_service` 的
  `DeepMarketDataService` 自建实例替换为 `runtime.deep_service`。

Worker / MCP / HTTP / CLI 现全部出自同一 `build_v3_runtime`，唯一差异 =
engine 副作用策略（F6-01 语义补完）。

**测试**：`test_v3_runtime_factory.py` 新增 Case C：structure_service
类型、`structure_service._bars is runtime.intraday_market_data` 同源、
Worker/MCP provider 同源、deep/structure 共享 provider。
