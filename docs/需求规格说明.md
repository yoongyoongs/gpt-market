# gpt-market V3 需求规格说明

> 文档版本：V3 Architecture Baseline 1.0 配套需求  
> 状态：实施前基线  
> 事实说明：本文同时描述当前已实现能力和 V3 待实现需求；状态列是判断依据，不能把待实现需求视为现有功能。

## 1. 文档目的

本文回答“系统为什么建设、为谁服务、必须提供什么能力、怎样才算满足需求”。技术实现方式分别由《技术架构设计》《数据库设计》《详细设计》和《架构设计实施稿》约束。

## 2. 产品定位

gpt-market 当前是只读 A 股行情 Remote MCP 与 GPT Web 服务。V3 在保留 V1/V2 基线的前提下，将其扩展为面向单个投资者、以 ChatGPT Web 为主要 AI 客户端的“事实—分析—确认—交易记录—持仓—复盘”决策支持系统。

系统不承诺收益，不提供自动下单，不把 AI 建议冒充真实成交，也不把第三方估算数据冒充官方事实。

## 3. 用户与参与者

| 参与者 | 主要职责 | 当前状态 |
|---|---|---|
| 单个投资者 | 发起分析、确认 AI 结果、录入真实成交、审批策略 | 当前及 V3 |
| ChatGPT Web | 横向比较、正反分析、Action/Entry/Review 判断 | V3 主要 AI 客户端 |
| 行情与 Evidence Provider | 提供外部事实数据 | 行情部分已实现，Evidence 待实现 |
| 运维/开发者 | 部署、监控、修复、迁移和审计 | 当前及 V3 |
| 未来模型/Bridge/Broker | 自动模型调用、网页同步、券商连接 | V4，不属于 V3 |

## 4. 核心原则

1. 系统负责可验证事实，AI 负责最终综合判断，用户确认真实资金行为；
2. V1/V2 保持兼容，V3 通过独立 Router、Schema、Worker 和 Feature Flag 上线；
3. Recall 是发现加速器，不是全市场访问权限墙；
4. 任何统一固定总分不得替代 AI 的候选横向判断；
5. Decision 不可修改，Review 只追加，Trade Ledger 不可变；
6. Replay 以 `known_at` 和数据修订为边界，禁止未来数据泄漏；
7. 缺失、冲突、陈旧和 `UNKNOWN` 必须显式返回；
8. 当前不依赖模型 API、浏览器 Bridge 或 ChatGPT 自动写服务器。

## 7. 非功能需求

### 7.1 一致性

- MCP、REST、GPT Web 必须复用相同事实 Service；
- 同一 Snapshot/Feature Run/Context Pack 必须可通过 ID 和 Hash 复现；
- Bundle 同一 Atomic Group 全部成功或全部回滚，不同组互不丢失；
- Position 可由 Opening Position、Adjustment 与 Trade Ledger 重建。

### 7.2 性能

- 常用 READ API 目标 P95 < 200ms；
- Universe Query、Comparison Pack、Position Context 目标 P95 < 500ms；
- Single AI Import 目标 P95 < 500ms；
- 30 股票 Bundle 预校验/确认目标 P95 < 1s，需实测确认；
- `/live` 必须只读缓存，不等待 Provider。

### 7.3 可用性与降级

- Provider 支持限流、重试、熔断、Fallback 和 Last-Known-Good；
- 后台刷新失败保留最近成功快照；
- 数据陈旧、覆盖不足和来源冲突必须显式返回；
- V3 故障可关闭 Feature Flag，继续运行 V1/V2。

### 7.4 安全与隐私

- Secret、Token、密码和真实交易截图不得进入 Git；
- 市场公共数据与 Portfolio 敏感数据保留独立 Scope；
- WRITE/Import 需要已认证的人类 UI 和确认；
- AI、OCR、Bridge 和外部 Agent 不能直接写真实 Ledger 或激活策略；
- 外部 Evidence 内容不能控制 Agent Prompt 或工具。

### 7.5 可维护性

- 业务核心不依赖特定模型 SDK；
- 数据对象保存来源、时点、版本、覆盖、置信度、陈旧和错误；
- Schema、Migration、Feature、Prompt、Strategy 和 Guardrail 均版本化；
- 每完成一个步骤必须更新工作状态、测试、中文提交并推送。

## 8. V3 范围外

- 自动下单、券商 API 和无人确认交易；
- Browser Bridge、DOM 监听和 ChatGPT 自动 POST；
- OpenAI/Claude/Gemini 等模型 API 和多 Agent 辩论；
- AI 自动激活正式 Strategy；
- 多用户企业级权限体系；
- 保证收益、荐股承诺或替用户承担投资决策。

## 9. 验收总则

1. 每项需求必须有代码、测试、数据或明确 `UNKNOWN` 证据；
2. “设计完成”不等于“功能实现”；
3. Phase 验收以《架构设计实施稿》第 30 章为阶段门禁；
4. 功能实现状态统一维护在《功能清单与开发状态》；
5. 实际工作进度统一维护在《工作状态》；
6. 需求变更先更新本文件与追踪关系，再进入实现。
