## K 线字段

`klines` 每行顺序由 `fields2` 确定：

```text
f51 时间,f52 开盘,f53 收盘,f54 最高,f55 最低,f56 成交量(手),f57 成交额(元),
f58 振幅(%),f59 涨跌幅(%),f60 涨跌额(元),f61 换手率(%)
```

服务统一输出时间、OHLC、成交量（股）和成交额（元）。`fqt=1` 表示前复权。分钟周期的时间格式为 `YYYY-MM-DD HH:MM`，日/周/月为 `YYYY-MM-DD`。

## 列表与板块

`/api/qt/clist/get` 使用 `fltt=2`。股票列表字段映射：`f12` 代码、`f14` 名称、`f2` 最新价、`f18` 昨收、`f17` 今开、`f15` 最高、`f16` 最低、`f3` 涨跌幅、`f4` 涨跌额、`f5` 成交量（手）、`f6` 成交额、`f8` 换手率、`f10` 量比、`f7` 振幅、`f124` Unix 时间。

板块字段：`f12` 板块代码、`f14` 名称、`f3` 涨跌幅、`f6` 成交额、`f104` 上涨家数、`f105` 下跌家数。公开响应未提供经本项目可靠验证的板块涨停家数，因此第一版返回 `null`，不推测。

## 时间戳语义核验

公开接口及东方财富公开页面没有提供可验证的 f86/f124 官方字段契约。实测中，A 股收盘后该值可能晚于 15:00（例如 `2026-08-27T15:34:15+08:00`），因此无法把它证明或解释为“交易所最后成交时间”。

既有 MCP/JSON 合约为保持兼容仍保留 `source_timestamp`；新增 Live Refresh HTML 使用以下无歧义名称：

- `market_timestamp`：当前 Provider 未提供可证明的交易所市场时间，显示“不可用”；
- `provider_timestamp`：f86/f124 转换后的 Provider 更新时间；
- `fetch_timestamp`：服务本次获取/组装标准对象的时间；
- `timestamp_semantics`：f86/f124 为 `provider_update_time`，字段缺失而回退抓取时间时为 `fetch_time`。

任何界面和文档都不得把 f86/f124 冒充为最后成交时间。

## 可用性结论

- 接口可能出现 TLS 连接被服务端直接关闭；客户端限定 5 秒、最多 3 次请求并使用 0.2/0.4 秒指数退避。
- `ulist.np/get` 在本次实测中返回了疑似混淆数据，未作为批量行情来源。少量代码使用 `asyncio.gather` 并发；全市场使用一次 `clist/get`。
- 无可信行情时抛出 provider error，由 REST 返回 HTTP 503、MCP 返回结构化 `ok=false`，不使用历史值冒充实时值。
